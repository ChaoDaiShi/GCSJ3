## 3. 根因：城镇样本本身不是建成区

在 7 月影像上逐面统计 NDVI / NDBI：

| 类 | NDVI 均值 | NDBI 均值 |
| --- | ---: | ---: |
| 城镇（8 面） | **0.471** | −0.139 |
| 耕地 | 0.614 | −0.238 |
| 林草 | 0.710 | −0.337 |
| 水体 | 0.270 | −0.313 |

建成区正常应 NDVI < 0.3、NDBI > 0。城镇类 8 面里 **6 面 NDVI > 0.40**（最高 0.600），
城镇与耕地 NDVI 只差 0.14。原因是这 32 个面在 2 月影像上标注，新都 2 月的休耕裸田、
翻耕地、待建空地在灰度上与建成区几乎一致，被当成了城镇。

模型于是学到「NDVI≈0.47 ⇒ 城镇」，而 7 月该区间覆盖大量稀疏植被地物，
造成 43.8% 的建成区占比。1992 年 8 月影像上城镇类 NDVI 均值 0.408、4/8 面 > 0.40，
同样存在偏高，但没有 2021 严重。

## 4. 已生成的候选面

脚本：`tools/make_urban_candidates.py`。判据（与方案 §3.3 一致）：

- NDVI < 0.30；NDBI > −0.05；MNDWI < 0（排除水体）；
- 3×3 开运算后连片 ≥ 3 ha；
- 落在研究区内且特征栅格有效；
- 候选之间间距 ≥ 2.5 km，按（NDBI − NDVI）降序取 24 个。

产物：

| 文件 | 用途 |
| --- | --- |
| `data/samples/2021/urban_candidates.gpkg` | QGIS 复核图层（`review=0`、`label_source=candidate`） |
| `data/samples/2021/urban_candidates.csv` | 复核清单 |
| `reports/samples/2021_urban_candidates.md` | 判据、清单、旧面问题 |
| `reports/samples/2021_urban_candidates.json` | 机器可读清单 |
| `outputs/maps/candidates_2021_urban.png` | 7 月真彩色底图 + 候选编号 |

**交叉校验**：严格判据下全区「光谱上明确的建成区」只有 **22.5 km²**，
而分类器给出 216.6 km²。两者差一个数量级，说明候选判据偏保守（只取纯像元），
但也印证了分类结果严重高估。

## 5. 下一步

1. 人工在 QGIS 中从 24 个候选里选 8 个（每类 8 组要求，尽量分散到不同街镇）；
2. 确认后重建 `labels.gpkg` 的城镇类，删除 `data/processed/samples/2021/split.json` 重跑 02—05；
3. 若候选不够（如清流镇无纯建筑像元），放宽到 NDVI < 0.40 再筛一轮。
